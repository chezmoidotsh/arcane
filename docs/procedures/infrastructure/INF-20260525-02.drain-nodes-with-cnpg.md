## Procedure INF-20260525-02: Draining a node hosting CNPG instances

Node drains happen during Omni-driven Talos upgrades (see
[INF-20260525-00](./INF-20260525-00.upgrade-talos.md)) and any manual `kubectl drain`. This procedure documents what
happens to CloudNativePG (CNPG) pods when their node is drained.

### Behaviour

| Cluster shape                          | PDB (`<cluster>-primary`) | Drain behaviour                                                                  |
| -------------------------------------- | ------------------------- | -------------------------------------------------------------------------------- |
| `instances: 1`, `enablePDB: false`     | none                      | The only instance is evicted and recreated on its PVC: **short DB downtime**.    |
| `instances: 1`, `enablePDB` unset/true | `minAvailable: 1`         | Drain **blocks** (0 allowed disruptions) until a human intervenes. Do not do it. |
| `instances > 1`, PDB kept              | protects the primary      | The primary is switched over first, replicas are evicted one at a time.          |

Repository convention: every `instances: 1` cluster sets `enablePDB: false` (explicitly in raw `Cluster` manifests, by
chart default in `mutualized-cnpg-databases`). Single-instance clusters are accepted to have downtime during a node
upgrade; no data is lost since the PVC (Proxmox CSI, decoupled from the VM) is reattached when the pod is rescheduled.
`rhodes.akn` is production: its single-instance clusters (`openbao-database`, `grafana-database`) are briefly
unavailable while their worker is drained, so expect OpenBao and Grafana to lose their database for the duration of the
pod restart.

### Steps

1. Before the upgrade, check no single-instance cluster carries a PDB:

   ```sh
   kubectl get pdb -A | grep -- '-primary'
   kubectl get clusters.postgresql.cnpg.io -A -o custom-columns=NS:.metadata.namespace,NAME:.metadata.name,INST:.spec.instances,PDB:.spec.enablePDB
   ```

   Any `INST=1` cluster with a `-primary` PDB must be fixed in `src/` (`enablePDB: false`, then `dist:render`). Do not
   patch the live `Cluster` (ArgoCD selfHeal reverts it; `nodeMaintenanceWindow` is deprecated).

2. Drain/upgrade the node, then wait for the cluster to recover:

   ```sh
   kubectl get clusters.postgresql.cnpg.io -A   # expect "Cluster in healthy state"
   ```

3. For multi-instance clusters, verify the primary after the drain with `kubectl get cluster <name> -n <ns>`.
