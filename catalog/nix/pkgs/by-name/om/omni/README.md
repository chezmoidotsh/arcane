## Project

[Sidero Omni](https://omni.siderolabs.com) is the management platform for Talos Linux clusters (machine provisioning,
cluster lifecycle, SideroLink, OIDC-authenticated UI/API). Upstream:
[siderolabs/omni](https://github.com/siderolabs/omni), licensed BSL-1.1 (unfree in nixpkgs).

## Package contents

| Output               | Description                                                              |
| -------------------- | ------------------------------------------------------------------------ |
| `bin/omni`           | The server (static Go binary, `CGO_ENABLED=0`, web UI embedded)          |
| `passthru.ui`        | The web UI alone (`ui.nix`, vite build of `frontend/`, generated by npm) |
| `passthru.goModules` | Vendored Go modules (fixed-output, used to resolve `vendorHash`)         |

Files: `package.nix` (backend, version, source and vendor hashes) and `ui.nix` (frontend, npm hash). Built from source:
the UI is built first and copied into `internal/frontend/dist`, which the Go binary embeds. The repository is a Go
workspace; the build uses the root module only (`GOWORK=off`) and Go 1.27 as required by `go.mod`.

## Build

From this directory:

```sh
mise run pkg:build:native   # for this machine's system (Linux or Apple Silicon)
mise run pkg:build:cross    # for another system, in a container (NIX_SYSTEM, default x86_64-linux)
```

`pkg:build:cross` is not a real cross-compilation: it runs the build natively inside a `nixos/nix` container of the
target platform (`catalog/nix/.mise/tasks/helpers/pkg/build-in-container`), so a Mac without a Linux builder can produce Linux outputs. It
is fast when the container matches the host (`aarch64-linux` on Apple Silicon) and slow when it must be emulated
(`x86_64-linux`). Equivalent without mise, from `catalog/nix`: `nix build "path:.#omni"` (the `path:` reference does not
depend on the git index).

## Use

- **NixOS module** (the supported path): the `omni` LXC (`projects/chezmoi.sh/src/infrastructure/proxmox/lxc/omni`) sets
  `services.omni.package` to this package in its flake and runs it through its own `modules/omni.nix`.
- **Binary**: `nix run .#packages.x86_64-linux.omni -- --help`, or install `bin/omni` anywhere.
- **Container**: the package ships no image. Use upstream's `ghcr.io/siderolabs/omni`, or wrap the binary with
  `pkgs.dockerTools.buildLayeredImage { name = "omni"; contents = [ omni ]; config.Entrypoint = [ "/bin/omni" ]; }`.

## Workarounds and risks

Upstream builds Omni inside Docker with an online `npm ci`, a Go toolchain newer than nixpkgs' default and a Go
workspace. Reproducing that in the offline Nix sandbox needs the workarounds below. Each one is also commented where it
is applied (`package.nix`, `ui.nix`).

| Workaround                                                                | Why                                                                                                                                                                                                                                                                                                   | Risk                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Vendored `package-lock.json`** replaces upstream's lock (`ui.nix`)      | With upstream's lock an offline `npm ci` fails (`@vue/devtools-kit@8.1.5` does not satisfy `8.2.1`, `fsevents` and `unplugin` missing): online npm fetches the metadata it needs, offline it cannot. The vendored lock is upstream's `package.json` re-locked with `npm install --package-lock-only`. | **Not the dependency set upstream tests**: re-locking changed ~320 of ~840 versions (all within `package.json` ranges), so the UI may differ from upstream's release or break on a transitive update. Must be regenerated at each bump (`mise run pkg:update` does it); a stale lock makes `npm ci` fail loudly. Adds a ~400 KB file to the repository. |
| **`npmRebuildFlags = [ "--ignore-scripts" ]`** (`ui.nix`)                 | Upstream's `.npmrc` sets `strict-allow-scripts=true`, so the hook's `npm rebuild` refuses the install scripts of `core-js` and `esbuild`.                                                                                                                                                             | A dependency that needs its install script would be silently incomplete. None today (`esbuild` ships its binary as an optional dependency, `core-js` only prints a banner). Same as the hook's own `npm ci --ignore-scripts`, so no security setting is weakened.                                                                                       |
| **`fetcherVersion = 2`** for the npm cache (`ui.nix`)                     | The offline cache must hold the metadata `npm ci` requests, which version 1 lacks (`ENOTCACHED`).                                                                                                                                                                                                     | None known; it changes the cache hash.                                                                                                                                                                                                                                                                                                                  |
| **Go 1.27** (`buildGoModule.override { go = go_1_27; }`)                  | `go.mod` requires Go 1.27.1, newer than nixpkgs' default Go.                                                                                                                                                                                                                                          | Breaks if nixpkgs drops `go_1_27`, or when upstream moves to a newer Go: bump the override with `go.mod`.                                                                                                                                                                                                                                               |
| **`GOWORK=off`** (`package.nix`)                                          | The repository is a Go workspace (`.`, `./client`, `./hack/zstd-dict`); the root module reaches `./client` through a `replace`, so it builds alone.                                                                                                                                                   | The `hack/zstd-dict` module is not built (not needed for the server). A new workspace-only dependency would fail the build.                                                                                                                                                                                                                             |
| **UI copied into `internal/frontend/dist`** in `preBuild` (`package.nix`) | The Go binary embeds that directory; upstream fills it in its Docker `frontend` stage.                                                                                                                                                                                                                | If upstream moves the embed path, the binary would embed the placeholder page. Check the UI loads after a bump.                                                                                                                                                                                                                                         |
| **`allowUnfree`** in the catalog flake                                    | Omni is BSL-1.1, unfree in nixpkgs.                                                                                                                                                                                                                                                                   | Applies to every package of the flake's nixpkgs instance.                                                                                                                                                                                                                                                                                               |

Validation: built on `x86_64-linux` (as part of the `omni` LXC image, emulated container), `aarch64-linux` (native
container) and `aarch64-darwin`.

## Update

```sh
cd catalog/nix/pkgs/by-name/om/omni
mise run pkg:update -- <new-version>     # e.g. 1.12.3
mise run pkg:eval
```

`pkg:update` rewrites `version`, then resolves the source hash and `vendorHash`, re-locks the vendored
`package-lock.json` (`npm install --package-lock-only` on the new `frontend/package.json`, needs network) and resolves
the npm hash of `ui.nix`. Review the diff (the lockfile re-resolves many versions within their semver
ranges), build on Linux (`mise run pkg:build:native`), and check that `go.mod`'s Go version still matches `go_1_27` in
`package.nix`. The `# oripathy:` annotation above `version` is what Oripathy tracks: keep it on that line.
