# Migrate Kazimierz.AKN from Ansible + Docker Compose to NixOS

> [!NOTE] **Status: COMPLETED on 2026-10-10.** The cutover was done and validated in production the same day (Pangolin
> state restored, 4 containers running, Tailscale node registered, `tailscale serve` working). This file is kept as a
> historical record; the Ansible code it mentions has been removed from the tree. For a (re)install today, follow
> [BOOTSTRAP.md](./BOOTSTRAP.md). The decision is recorded in
> [ADR-016](../../../docs/decisions/016-kazimierz-nixos-over-ansible.md).

This document describes how to replace the Ubuntu + Ansible + Docker Compose setup of the Kazimierz.AKN VPS with a NixOS
host installed by `nixos-anywhere`, the way `rimbilliton.akn` is (see
[its bootstrap](../../rimbilliton.akn/docs/BOOTSTRAP.md), which this procedure follows closely). The NixOS definition
lives in `src/infrastructure/nixos/`. [BOOTSTRAP.md](./BOOTSTRAP.md) is the same install for a fresh instance, without state to restore.

> [!IMPORTANT] `nixos-anywhere` repartitions the boot volume. There is no side-by-side migration: the tenancy's Always
> Free A1 quota (2 OCPU / 12 GB) is fully used by `kazimierz-pangolin` and `rimbilliton-minecraft`, so a second instance
> cannot be created. Expect **a few minutes to tens of minutes of downtime of every service exposed through Pangolin**
> (the Newt tunnels reconnect by themselves afterwards). Plan it, and keep the backup of step 1 until step 7 is done.

## What changes

| Concern                | Before (Ansible role)                             | After (NixOS, `src/infrastructure/nixos/`)                                                 |
| ---------------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| OS / hardening         | `system_setup` (sshd, sysctl, UFW, fail2ban, DNS) | `configuration.nix` (same sshd/sysctl/fail2ban/DNS settings, NixOS firewall)               |
| Containers             | Docker Compose in `/opt/pangolin`                 | `modules/pangolin.nix`: `oci-containers`, same images, state in `/var/lib/pangolin/config` |
| Traefik / Pangolin cfg | Jinja2 templates                                  | Nix attrsets rendered to YAML; secrets rendered on tmpfs by sops-nix                       |
| GeoIP database         | `pangolin-geoip-update` timer                     | `modules/geoip.nix` (same source, same 02:15 schedule)                                     |
| Integration API        | `tailscale serve` run by Ansible                  | `pangolin-tailscale-serve` unit                                                            |
| Secrets                | `host_vars` encrypted with ansible-vault          | `secrets/kazimierz.sops.yaml` (SOPS + age, host key as recipient)                          |
| Deploys                | `ansible-playbook` over SSH                       | `nixos-rebuild switch --target-host` over the tailnet                                      |

Not ported, on purpose: `unattended-upgrades` and its Slack notification. NixOS is updated by bumping `flake.lock`
(`nonix flake update`) and running `nixos-rebuild`, which also gives you a rollback (`nixos-rebuild --rollback`).
Whether the host should reconcile itself automatically is the open question already tracked in
`docs/reports/20261008-manual-infrastructure-inventory.md` (item 11).

## Prerequisites

1. Same tooling as `rimbilliton.akn`: `mise install`, Docker, and every Nix command through `nonix`.
2. **Tailnet**: `tag:svc-pangolin` already exists (the Ansible setup uses it). The auth key is generated by the Pulumi
   stack (`tailscale:tailnet` and the Tailscale provider credentials must be set, same as `rimbilliton.akn`).
3. **Ansible vault password** (it was stored in `src/infrastructure/ansible/.vault-password.sops`, now removed), to read
   the values to copy into the SOPS file.
4. `ssh_authorized_keys` of the Pulumi stack: the private key must be in your SSH agent.

## Procedure

### 1. Check where the state lives, then back it up

Pangolin's state lives in `/opt/pangolin/config` **on the boot volume**, which the install wipes, so copy it out first
(it contains secrets, keep it encrypted at rest and out of the repo):

```bash
mise run nixos:backup   # hot copy, no downtime -> $KAZIMIERZ_BACKUP_DIR (default ~/.local/share/kazimierz.akn/backups)
```

(The task then also read the Ansible layout in `/opt/pangolin/config`; it now handles the NixOS layout only.)

`mise run nixos:oci:install` shows the latest backup and its age, warns if there is none (or if it is older than 24h),
offers to take one, and asks for confirmation before wiping the host.

- `db/`: Pangolin's SQLite database (users, sites, resources, API keys).
- `key`: Gerbil's WireGuard private key.
- `letsencrypt/acme.json`: the issued certificates (avoids re-requesting the wildcard right away).
- `config.yml`: for reference only, NixOS regenerates it.

### 2. Prepare the host key, the SOPS file and the restored state

```bash
cd projects/kazimierz.akn/src/infrastructure/nixos
mkdir -p extra/etc/ssh && ssh-keygen -t ed25519 -N '' -f extra/etc/ssh/ssh_host_ed25519_key
nonix run nixpkgs#ssh-to-age -- -i extra/etc/ssh/ssh_host_ed25519_key.pub   # host age key
```

Add that age key as a second recipient of the `kazimierz.akn` rule in `src/infrastructure/nixos/.sops.yaml`
(comma-separated after the admin key), then:

```bash
cp secrets/kazimierz.example.yaml secrets/kazimierz.sops.yaml   # fill it, see the comments in the file
sops --encrypt --in-place secrets/kazimierz.sops.yaml
# Already encrypted before adding the host key? `sops updatekeys secrets/kazimierz.sops.yaml` re-wraps it for both.
```

`pangolin_server_secret` **must be the current value** (from the Ansible `host_vars`): Pangolin's data is bound to it.
Put the backup where `nixos-anywhere --extra-files` will copy it onto the new root:

```bash
mkdir -p extra/var/lib/pangolin/config
tar -C extra/var/lib/pangolin/config -xzf <path of the backup>.tgz --exclude=./docker-compose.yml --exclude=./traefik
```

The binding IP, which Docker publishes ports 80/443 on (`pangolin.bindIp`), is the instance's private (VCN) address, the
only one its network interface has: the public IP is NAT-ed by OCI and never shows up on the host. It lives in
`extra/etc/pangolin/binding-ip`, git-ignored like the rest of `extra/` (and copied onto the host by `nixos-anywhere`).
`mise run nixos:binding-ip` writes it from the Pulumi output (`pulumi stack output bindingIp`) and
`mise run nixos:oci:install` / `nixos:oci:update` do it first; the platform reads it at evaluation time. The build
refuses a missing or empty file. Set the public key in `configuration.nix` too. Do not commit `extra/`.
`secrets/kazimierz.sops.yaml` is now committed (encrypted). If the build complains about an untracked path,
`git add -N flake.lock` (a flake only sees files known to git; the tasks already run `git add -f -N` on the binding IP
file).

### 3. Free the Tailscale name

The new host registers as `kazimierz-akn`, the name the Pulumi stacks' `pangolin:url` is built from. Delete the current
`kazimierz-akn` machine from the Tailscale admin console first (otherwise the new one becomes `kazimierz-akn-1`).

### 4. Install NixOS

SSH is closed on the OCI network security group: `pulumi config set unsecure true && pulumi up` (back to `false` once
done). The instance still runs the stock Ubuntu, which lacks `cpio`:

```bash
IP=<public IP of kazimierz-pangolin>   # OCI console; the Pulumi stack does not export it
ssh ubuntu@"$IP" 'sudo apt-get update -qq && sudo apt-get install -y cpio'
```

Then install, exactly as for `rimbilliton.akn` (troubleshooting table in
[its bootstrap](../../rimbilliton.akn/docs/BOOTSTRAP.md#4-install-nixos)):

```bash
mise run nixos:oci:install ubuntu@"$IP"
```

The task refreshes the binding IP (`nixos:binding-ip`), then runs `nixos-anywhere` (pinned by commit) through `nonix`
with `--flake .#kazimierz-akn-aarch64 --extra-files extra --kexec-extra-flags --kexec-syscall`. `nonix` forwards your
SSH agent to the container, and that agent must hold the key matching `ssh_authorized_keys` in the Pulumi config:

> [!IMPORTANT] **macOS (OrbStack, Docker Desktop): the containers run in a Linux VM**, so `nonix` cannot mount your
> agent's socket directly (the file shows up, but connecting to it fails with `Connection refused`). It uses the relay
> the runtime offers instead, `/run/host-services/ssh-auth.sock`, which forwards the agent of the **macOS login
> session** (the `SSH_AUTH_SOCK` known to `launchd`), not the one of your current shell. With the default macOS agent
> nothing is needed. With a custom agent (Bitwarden, Secretive, 1Password, ...), point `launchd` at its socket and
> restart the runtime:
>
> ```bash
> launchctl getenv SSH_AUTH_SOCK                                  # what the relay will forward
> launchctl setenv SSH_AUTH_SOCK "<path of your agent's socket>"  # e.g. $HOME/.bitwarden-ssh-agent.sock
> orb stop && orb start                                           # OrbStack; restart Docker Desktop otherwise
> ```
>
> `launchctl setenv` does not survive a reboot. Check what the container sees before an install: your key must be listed
> (`docker run --rm -v /run/host-services/ssh-auth.sock:/ssh-agent -e SSH_AUTH_SOCK=/ssh-agent nixos/nix ssh-add -l`).
> On Linux the socket is mounted directly from `$SSH_AUTH_SOCK`.

`nixos-anywhere` cannot detect the target architecture, so the flake exposes one output per architecture (`platforms/`):
`.#kazimierz-akn-aarch64` is the OCI A1 (UEFI, production) and `.#kazimierz-akn-x86_64` an x86_64 legacy-BIOS VM. There
is no un-suffixed output. To rehearse this procedure on a Proxmox KVM test VM instead of the real host:

```bash
mise run nixos:e2e <user@host>   # the target is mandatory; its address (IP, DNS name or ssh_config alias) becomes the binding IP
```

The Oracle arm64 kernel needs `--kexec-syscall` (the task passes it). If the run fails after the kexec, the host is no
longer Ubuntu: resume as `root` from the disk step (`cd src/infrastructure/nixos`, then
`nonix run github:nix-community/nixos-anywhere -- --flake .#kazimierz-akn-aarch64 --extra-files extra --phases disko,install,reboot --target-host root@"$IP"`;
see the rimbilliton troubleshooting table).

### 5. Verify

```bash
tailscale status | grep kazimierz-akn
ssh root@kazimierz-akn 'systemctl status docker-pangolin docker-gerbil docker-traefik docker-error-pages \
  pangolin-prepare pangolin-tailscale-serve; docker ps; tailscale serve status'
curl -sI https://pangolin.chezmoi.sh | head -n1
```

- The dashboard answers with a valid certificate and your existing admin account works (no `/auth/initial-setup`: the
  database was restored).
- The sites (Newt on `lungmen.akn` and `rhodes.akn`) show as online in the dashboard.
- The Pulumi stacks still reach the Integration API: `pulumi preview` in `rhodes.akn`/`lungmen.akn` shows no diff on the
  `pangolin` resources.
- Close SSH again: `pulumi config set unsecure false && pulumi up`.

### 6. Day-2 operations

```bash
mise run nixos:oci:update
```

It refreshes the binding IP from the Pulumi stack, then runs
`nixos-rebuild switch --flake .#kazimierz-akn-aarch64 --target-host root@kazimierz-akn` (nixos-rebuild taken from the
nixpkgs revision locked in `flake.lock`) over the tailnet.

Image tags and their digests are bumped together in `modules/pangolin.nix`.

## Lessons learned during the cutover

Gotchas hit during the real run, now in the [troubleshooting table of BOOTSTRAP.md](./BOOTSTRAP.md#troubleshooting):

- Ubuntu OCI images restrict `/root/.ssh/authorized_keys` with a `command="echo 'Please login as the user ubuntu'..."`
  prefix: copy the `ubuntu` user's keys to root, or install as `ubuntu@`.
- The host's sshd has `MaxAuthTries 3`: an agent offering several keys fails with `Too many authentication failures`
  (`IdentitiesOnly` or a dedicated agent).
- On macOS the `nonix` container only sees the `launchd`-session agent (see the note in step 4).
- The Tailscale auth key (`tailscaleAuthKey`, single use, 7 days) is consumed by a first boot: regenerate it with
  `pulumi up --replace <urn of kazimierz-tailscale-key>` and update `tailscale_authkey` in the SOPS file. The old node
  must be deleted from the admin console beforehand, otherwise the new one becomes `kazimierz-akn-1`.
- `pulumi stack output` needs `--stack kazimierz_akn.live` (the mise tasks pass it).

## Rollback (historical)

The boot volume was wiped by step 4, so there was no in-place rollback after that point: the plan was to recreate the
instance (`pulumi up` with the instance replaced, a stock Ubuntu again), run the Ansible playbook and restore `db/`,
`key` and `letsencrypt/` from the backup into `/opt/pangolin/config`. The cutover succeeded and the Ansible code has
been removed, so this path no longer exists: it is in the Git history (commit before the removal) if ever needed.
